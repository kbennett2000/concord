# Concord v1.3.0

The first minor release since v1.2.0 brings **private study Bibles** (v8), **one A–Z list for topics**, and three fixes. Every `/v1` change adds something. No key or endpoint is removed, renamed or retyped. One sort order changes, described below.

```bash
docker pull ghcr.io/kbennett2000/concord:v1.3.0     # or :latest
docker run -d -p 8000:8000 ghcr.io/kbennett2000/concord:v1.3.0
```

## Your own study Bible (v8)

Concord can now serve a **study Bible you own**, meaning its translation text and everything printed around it, through the same API. A study Bible is copyrighted, so Concord ships the capability, never the content. You supply the data under the gitignored `data/private/`, and it is baked only into your own `bible.db` and image (`make docker-build-private`, for your LAN only, never pushed).

- **Note fields** ([ADR-0011](https://github.com/kbennett2000/concord/blob/v1.3.0/docs/adr/ADR-0011-v8-note-fields.md)): every note gains `label`, `title`, `text_format`, `passages` and `image`, appended after the existing keys and `null`/`[]` when unused. `text_format: "markdown"` marks Markdown text whose `ref:` links a client can jump to. There are two new note types, `article` and `chart`. `GET /v1/translations` gains `note_count` and `document_count` for each translation.
- **Images** ([ADR-0012](https://github.com/kbennett2000/concord/blob/v1.3.0/docs/adr/ADR-0012-images-and-documents.md)): `GET /v1/translations/{translation}/assets/{name}` serves a chart or figure as its own bytes (JPEG or PNG), with an immutable ETag.
- **Documents** (ADR-0012): `GET /v1/translations/{translation}/documents` (filter with `?book=` and `?kind=`) and `GET /v1/translations/{translation}/documents/{slug}`. These hold book introductions, front matter, a reading plan and notes about the edition, as Markdown with `ref:` links and the images each document places.
- **Private topics and sources** ([ADR-0013](https://github.com/kbennett2000/concord/blob/v1.3.0/docs/adr/ADR-0013-private-topics-and-sources.md)): a study Bible's topical index loads beside Nave's from `data/private/topics/`. Every topic carries `source`. `GET /v1/topics` gains `?source=` and appends `source` and `sources` (each loaded source with its count), and an unknown source is `400 unknown_source`.
- **A converter for one study Bible**, the Every Man's Bible (NLT). It reads your own copy of the book and writes everything under `data/private/` ([emb-ingest](https://github.com/kbennett2000/concord/blob/v1.3.0/docs/v8/emb-ingest.md)). The file contracts are in [notes-ingest](https://github.com/kbennett2000/concord/blob/v1.3.0/docs/v4/notes-ingest.md), [documents-ingest](https://github.com/kbennett2000/concord/blob/v1.3.0/docs/v8/documents-ingest.md) and [topics-ingest](https://github.com/kbennett2000/concord/blob/v1.3.0/docs/v8/topics-ingest.md). Only load data you have the legal right to use.

**The published image carries none of it.** It holds 15 translations (13 English plus the SBL Greek NT and the Hebrew OT), 0 notes, 0 images, 0 documents, and Nave's Topical Bible (5,319 topics) as its only topical source. So on the published image every `note_count` and `document_count` is `0`, notes and documents answer `200` with an empty list, an image name is a `404`, and `/v1/topics` lists Nave's alone.

## Topics: one A–Z list

`GET /v1/topics` and `GET /v1/verses/{ref}/topics` now order by name **ignoring case**, then by id. Topics from different sources therefore interleave in one alphabet, names equal but for case keep a stable order, and paging stays stable. Until now the order was binary, which put every all-capitals name before every mixed-case name of the same letter.

**This changes Nave's order in exactly one place.** "ANGEL (a spirit)" now comes before "ANGEL (Holy Trinity)"; they were the other way round, at positions 298 and 299 (counting from 0). On the published image, a list page or reverse lookup that holds both topics changes by that swap and nothing else. Examples are `/v1/topics?limit=200&offset=200`, `?offset=250` at the default limit, section A's second page, `?q=angel`, and the reverse lookup of the 35 verses and 21 chapters that cite both. Every other Nave's position is unchanged: of 42,813 topics responses compared before and after this change, 61 differ, each by that swap alone.

Separately from the order, every topic now carries `source`, which on the published image is always `"Nave's Topical Bible"`, and `/v1/topics` appends `source` and `sources` (see above).

## Fixes

- **Word-study tokens carry their verse** (#69, [ADR-0009](https://github.com/kbennett2000/concord/blob/v1.3.0/docs/adr/ADR-0009-additive-fields-on-v1-responses.md)): each token of `GET /v1/verses/{ref}/words` gains `book`, `chapter`, `verse` and `reference`, appended. A multi-verse request no longer has to be split on `position` resets.
- **Chapter-to-chapter:verse ranges** (#73, [ADR-0010](https://github.com/kbennett2000/concord/blob/v1.3.0/docs/adr/ADR-0010-chapter-to-chapter-verse-ranges.md)): `Judges 13-14:11` now parses, as `Judges 13:1-14:11`. `3:16-4` is still rejected, since its end would need a verse count the parser doesn't have.
- **Fused section headings** (#67): 2,452 headings that had been glued onto the verse before them, across 12 translations, are back where they belong as headings. Verse text, search and the WEB embeddings no longer carry them.

## Also

- **OpenAPI:** the notes, notes-search, translations, documents, assets and topic endpoints now declare their response bodies in `docs/openapi.json`.
- **Faster private rebuilds:** the embedding bake has its own Docker stage, keyed on the WEB verse list, so a rebuild after a data or code change reuses it (about a minute, not about thirty).
- **A caching caveat.** Responses are cached `immutable`, so a browser or proxy holding a body from an earlier version can keep serving it, without the new keys or in the old topics order, until it fetches again. Treat the appended keys as optional, and clear your cache after upgrading if it matters.

The full reference is in [`docs/API.md`](https://github.com/kbennett2000/concord/blob/v1.3.0/docs/API.md).
